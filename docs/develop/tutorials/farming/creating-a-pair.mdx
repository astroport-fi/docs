# Creating a Pair

## Overview

The [Factory](/docs/develop/smart-contracts/factory) creates new pool contracts and keeps a registry of them. Anyone can create a pool for a new asset pair with `create_pair`, as long as the pool type is not permissioned or disabled. The factory registers one pool per asset pair: if a pool for the pair already exists, whatever its type, `create_pair` fails with `Pair was already created`.

| Chain | Factory |
| ----- | ------- |
| Terra | `terra14x9fr055x5hvr48hzy2t4q7kvjvfttsvxusa4xsdcy702mnzsvuqprer8r` |
| Neutron | `neutron1hptk0k5kng7hjy35vmh009qd5m6l33609nypgf2yc6nqnewduqasxplt4e` |

Pool types anyone can create on both chains:

| `pair_type` | Pool | Swap fee | Notes |
| ----------- | ---- | -------- | ----- |
| `{"xyk": {}}` | [Constant product](/docs/develop/smart-contracts/swap-pairs/constant-product-pools) | 0.30% | No `init_params` needed |
| `{"stable": {}}` | [Stableswap](/docs/develop/smart-contracts/swap-pairs/stableswap-pools) | 0.05% | `init_params` with `amp` |
| `{"custom": "concentrated"}` | [PCL](/docs/develop/smart-contracts/swap-pairs/passive-concentrated-liquidity-pools) | Dynamic, set in the pool parameters | `init_params` with the PCL parameters |

On Neutron the factory also offers `{"custom": "concentrated_duality_orderbook"}`. Transmuter pools are permissioned. The live list, with fees and flags, is the factory's `config` query (`pair_configs`). The Maker's share of the swap fee goes to the protocol (see [Maker](/docs/develop/smart-contracts/tokenomics/maker)); the rest stays in the pool for liquidity providers.

<Admonition type="info" title="NOTE">

Stableswap and PCL pools need the decimals of every native asset in the pool. They read them from the native coin registry (Terra `terra1zuf8fla02926nhpfvk09k2pg6qv9aayflp0qt4a0msppu2h4exqs6af275`, Neutron `neutron1jzzv6r5uckwd64n6qan3suzker0kct5w565f6529zjyumfcx96kqtcswn3`). Check a denom with `{"native_token": {"denom": "..."}}`. If it isn't registered, anyone can register it with `{"register": {"native_coins": [["<denom>", 6]]}}`, sending a small amount of each listed coin with the message; the coins are returned.

</Admonition>

## Constant Product Pools

`create_pair` takes the `pair_type` and the two assets as [`AssetInfo`](/docs/develop/smart-contracts/common-types#assetinfo) values. This example creates an xyk pool for a new tokenfactory token against NTRN on Neutron:

```json
{
  "create_pair": {
    "pair_type": {
      "xyk": {}
    },
    "asset_infos": [
      {
        "native_token": {
          "denom": "factory/neutron1...creator/mytoken"
        }
      },
      {
        "native_token": {
          "denom": "untrn"
        }
      }
    ]
  }
}
```

With CosmJS (see [Swapping](../trading/swapping#setup) for the client setup):

```js
const factory = "neutron1hptk0k5kng7hjy35vmh009qd5m6l33609nypgf2yc6nqnewduqasxplt4e";

const assetInfos = [
  { native_token: { denom: "factory/neutron1...creator/mytoken" } },
  { native_token: { denom: "untrn" } },
];

const result = await signingClient.execute(
  sender,
  factory,
  { create_pair: { pair_type: { xyk: {} }, asset_infos: assetInfos } },
  "auto"
);

console.log(result.transactionHash);
```

For a CW20 asset, use `{"token": {"contract_addr": "..."}}` instead of `native_token`.

## Stableswap Pools

Stableswap pools take a base64-encoded `init_params` with the amplification `amp`:

```json
{
  "create_pair": {
    "pair_type": {
      "stable": {}
    },
    "asset_infos": [
      {
        "native_token": {
          "denom": "ibc/...stable-a"
        }
      },
      {
        "native_token": {
          "denom": "ibc/...stable-b"
        }
      }
    ],
    "init_params": "eyJhbXAiOjEwfQ=="
  }
}
```

`eyJhbXAiOjEwfQ==` is the base64 encoding of `{"amp":10}`. With CosmJS, `toBinary` does the encoding:

```js
import { toBinary } from "@cosmjs/cosmwasm-stargate";

const result = await signingClient.execute(
  sender,
  factory,
  {
    create_pair: {
      pair_type: { stable: {} },
      asset_infos: [
        { native_token: { denom: "ibc/...stable-a" } },
        { native_token: { denom: "ibc/...stable-b" } },
      ],
      init_params: toBinary({ amp: 10 }),
    },
  },
  "auto"
);
```

## PCL Pools

PCL pools use `{"custom": "concentrated"}` and a base64-encoded `ConcentratedPoolParams` as `init_params` (amplification, gamma, fees, initial price scale and more). The parameters and their meaning are documented on the [PCL pool page](/docs/develop/smart-contracts/swap-pairs/passive-concentrated-liquidity-pools). Pick parameters from an existing pool with similar assets (query its `config`) unless you know what you need.

## Finding the Pool Address

After the transaction, look up the new pool with the factory's `pair` query. The order of `asset_infos` doesn't matter.

```json
{
  "pair": {
    "asset_infos": [
      {
        "native_token": {
          "denom": "factory/neutron1...creator/mytoken"
        }
      },
      {
        "native_token": {
          "denom": "untrn"
        }
      }
    ]
  }
}
```

The response is a `PairInfo`:

```json
{
  "asset_infos": [
    {
      "native_token": {
        "denom": "factory/neutron1...creator/mytoken"
      }
    },
    {
      "native_token": {
        "denom": "untrn"
      }
    }
  ],
  "contract_addr": "neutron1...pool",
  "liquidity_token": "factory/neutron1...pool/astroport/share",
  "pair_type": {
    "xyk": {}
  }
}
```

`liquidity_token` is the pool's LP token. Pools created on Neutron today mint a native tokenfactory LP token (`factory/<pool address>/astroport/share`). The pool codes the Terra factory uses mint a CW20 LP token, so `liquidity_token` is a `terra1...` contract address. Older pools on both chains may use CW20 LP tokens. The LP token type decides how you withdraw liquidity and stake in Incentives: see [Providing/Withdrawing Liquidity](providing-withdrawing-liquidity) and [Staking/Unstaking LP Tokens](staking-unstaking-lp-tokens).
