# Multi-hop Routing

## Overview

When there is no pool for the pair you want, or a better price is available through another asset, the [Router](/docs/develop/smart-contracts/router) swaps through several pools in one transaction. Hops execute one after the other; the last hop sends the ask asset to you.

Two router versions are live on each chain. **Router 2.0 is the recommended one** and is what this page documents.

| Chain | Router 2.0.0 (recommended) | Router 1.3.1 |
| ----- | -------------------------- | ------------ |
| Terra | `terra1txm8xcy8mete9e5zh5ktqr4jm4cq4ja8djttg3zkqll64x4ksq7qknaesf` | `terra18plp90j0zd596zt3zdsf0w9vvk5ukwlwzwkksxv9mdu8rscat9sqndk5qz` |
| Neutron | `neutron1xuh7nqt486gkvkxdwt773fzs5uptxy0ylzehm3spq7rx8r2kaspqzu0hv6` | `neutron1rwj6mfxzzrwskur73v326xwuff52vygqk73lr7azkehnfzz5f5wskwekf4` |

What changed in Router 2.0:

- **`pool_swap` hops.** Besides `astro_swap` (the factory looks up the pool for the asset pair), a hop can name the pool by address. This lets a route use pools the factory doesn't know about, such as the USDC transmuter on Terra.
- **`minimum_receive` is required** and must be greater than zero. It is the only price check: the pools' own spread checks are turned off on every hop, and there is no `max_spread` parameter.
- **Nested routes are refused.** A route can't start while another route is running (`A swap route is already in progress`).
- A route has at most 50 hops, and each hop's offer asset must be the previous hop's ask asset.

Router 1.x keeps its old API (`astro_swap` and `native_swap` hops, optional `minimum_receive` and `max_spread`) and can't be migrated to 2.x. Existing integrations keep working; new integrations should use 2.0.

## Swap Operations

A route is a list of `SwapOperation` values.

`astro_swap` swaps in the factory's pool for this asset pair:

```json
{
  "astro_swap": {
    "offer_asset_info": {
      "native_token": {
        "denom": "uluna"
      }
    },
    "ask_asset_info": {
      "native_token": {
        "denom": "ibc/2C962DAB9F57FE0921435426AE75196009FAA1981BF86991203C8411F8980FDB"
      }
    }
  }
}
```

`pool_swap` swaps in the pool at `pool_addr`. The router checks that the pool's `pair` query reports this address and both assets:

```json
{
  "pool_swap": {
    "pool_addr": "terra1p3sea2vjewtr9ap4hv7nc75k5jc852ftf0w5u06wsk420y5urc9s9xtxdj",
    "offer_asset_info": {
      "native_token": {
        "denom": "ibc/2C962DAB9F57FE0921435426AE75196009FAA1981BF86991203C8411F8980FDB"
      }
    },
    "ask_asset_info": {
      "native_token": {
        "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
      }
    }
  }
}
```

<Admonition type="caution" title="Only route through pools you trust">

`pool_swap` accepts any address. The `pair` check catches mistyped routes, but it can't prove that a contract is a genuine Astroport pool. Build `pool_swap` hops only from pools you have verified, for example from the [Contract Addresses](/docs/develop/smart-contracts/contract-addresses) page or the factory's `pairs` query.

</Admonition>

## Example Route

The examples below swap 10 LUNA into USDC.inj on Terra in two hops:

1. LUNA to USDC (Noble) in the LUNA/USDC pool, found by the factory (`astro_swap`).
2. USDC (Noble) to USDC.inj in the USDC transmuter, given by address (`pool_swap`).

| Asset | Denom on Terra |
| ----- | -------------- |
| LUNA | `uluna` |
| USDC (Noble) | `ibc/2C962DAB9F57FE0921435426AE75196009FAA1981BF86991203C8411F8980FDB` |
| USDC.inj | `ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B` |
| USDC transmuter (pool) | `terra1p3sea2vjewtr9ap4hv7nc75k5jc852ftf0w5u06wsk420y5urc9s9xtxdj` |

A Neutron route has the same shape. For example NTRN to USDC through ASTRO uses two `astro_swap` hops, `untrn` to `factory/neutron1ffus553eet978k024lmssw0czsxwr97mggyv85lpcsdkft8v9ufsz3sa07/astro` and then ASTRO to `ibc/B559A80D62249C8AA07A380E2A2BEA6E5CA9A6F079C912C3A9E9B494105E4F81` (USDC), sent to the Neutron Router 2.0.

## Simulating a Route

`simulate_swap_operations` takes the offer amount (in base units) and the same operations you will execute:

```json
{
  "simulate_swap_operations": {
    "offer_amount": "10000000",
    "operations": [
      {
        "astro_swap": {
          "offer_asset_info": {
            "native_token": {
              "denom": "uluna"
            }
          },
          "ask_asset_info": {
            "native_token": {
              "denom": "ibc/2C962DAB9F57FE0921435426AE75196009FAA1981BF86991203C8411F8980FDB"
            }
          }
        }
      },
      {
        "pool_swap": {
          "pool_addr": "terra1p3sea2vjewtr9ap4hv7nc75k5jc852ftf0w5u06wsk420y5urc9s9xtxdj",
          "offer_asset_info": {
            "native_token": {
              "denom": "ibc/2C962DAB9F57FE0921435426AE75196009FAA1981BF86991203C8411F8980FDB"
            }
          },
          "ask_asset_info": {
            "native_token": {
              "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
            }
          }
        }
      }
    ]
  }
}
```

The response is the amount of the last ask asset you would receive, in base units:

```json
{
  "amount": "394395"
}
```

`reverse_simulate_swap_operations` answers the opposite question: it takes `ask_amount` and the operations and returns the offer amount needed, as a plain string (for example `"25377928"`).

## Setting `minimum_receive`

`minimum_receive` is the least amount of the final ask asset, in base units, that the recipient must receive. After the last hop the router compares the recipient's balance before and after the route and reverts the whole transaction if the difference is smaller.

Take your expected output and subtract the slippage you accept. With the simulation above and 1% slippage:

```text
expected        = 394395                      (0.394395 USDC.inj)
minimum_receive = 394395 * 99 / 100 = 390451  (rounded down)
```

<Admonition type="caution" title="minimum_receive is your only protection">

Router 2.0 disables the pools' own spread checks, so a route with `"minimum_receive": "1"` is accepted but protects almost nothing. Set it from a price you trust. A simulation taken just before the swap protects you against the price moving between query and execution; a quote you computed independently also protects you against a pool whose price was already moved.

</Admonition>

## Native Routing

When the first offer asset is a native token, call `execute_swap_operations` on the router and attach the offer amount as funds.

```json
{
  "execute_swap_operations": {
    "operations": [
      {
        "astro_swap": {
          "offer_asset_info": {
            "native_token": {
              "denom": "uluna"
            }
          },
          "ask_asset_info": {
            "native_token": {
              "denom": "ibc/2C962DAB9F57FE0921435426AE75196009FAA1981BF86991203C8411F8980FDB"
            }
          }
        }
      },
      {
        "pool_swap": {
          "pool_addr": "terra1p3sea2vjewtr9ap4hv7nc75k5jc852ftf0w5u06wsk420y5urc9s9xtxdj",
          "offer_asset_info": {
            "native_token": {
              "denom": "ibc/2C962DAB9F57FE0921435426AE75196009FAA1981BF86991203C8411F8980FDB"
            }
          },
          "ask_asset_info": {
            "native_token": {
              "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
            }
          }
        }
      }
    ],
    "minimum_receive": "390451"
  }
}
```

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `operations` | `Vec<SwapOperation>` | The hops, in order (1 to 50) |
| `minimum_receive` | `Uint128` | Required, greater than zero. Least amount of the final ask asset the recipient must receive |
| `to` | `Option<String>` | Recipient of the final ask asset, if not the sender |

A complete CosmJS script (see [Swapping](swapping#setup) for the client setup):

```js
const router = "terra1txm8xcy8mete9e5zh5ktqr4jm4cq4ja8djttg3zkqll64x4ksq7qknaesf"; // Router 2.0.0
const usdc = "ibc/2C962DAB9F57FE0921435426AE75196009FAA1981BF86991203C8411F8980FDB";
const usdcInj = "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B";
const transmuter = "terra1p3sea2vjewtr9ap4hv7nc75k5jc852ftf0w5u06wsk420y5urc9s9xtxdj";

const native = (denom) => ({ native_token: { denom } });

const operations = [
  { astro_swap: { offer_asset_info: native("uluna"), ask_asset_info: native(usdc) } },
  { pool_swap: { pool_addr: transmuter, offer_asset_info: native(usdc), ask_asset_info: native(usdcInj) } },
];

const offerAmount = "10000000"; // 10 LUNA

// 1. Simulate
const { amount } = await client.queryContractSmart(router, {
  simulate_swap_operations: { offer_amount: offerAmount, operations },
});

// 2. Accept at most 1% less than the simulation (integer math, rounded down)
const minimumReceive = ((BigInt(amount) * 99n) / 100n).toString();

// 3. Execute, attaching the offer asset
const result = await signingClient.execute(
  sender,
  router,
  { execute_swap_operations: { operations, minimum_receive: minimumReceive } },
  "auto",
  "",
  [{ denom: "uluna", amount: offerAmount }]
);

console.log(result.transactionHash);
```

## CW20 Routing

When the first offer asset is a CW20 token, call `send` on the token contract with the router as `contract` and the base64-encoded `execute_swap_operations` message as `msg`. The amount comes from the `send`; the hook takes `operations`, `minimum_receive` and an optional `to`.

The decoded hook message:

```json
{
  "execute_swap_operations": {
    "operations": [
      {
        "astro_swap": {
          "offer_asset_info": {
            "token": {
              "contract_addr": "terra1...token"
            }
          },
          "ask_asset_info": {
            "native_token": {
              "denom": "uluna"
            }
          }
        }
      },
      {
        "astro_swap": {
          "offer_asset_info": {
            "native_token": {
              "denom": "uluna"
            }
          },
          "ask_asset_info": {
            "native_token": {
              "denom": "ibc/2C962DAB9F57FE0921435426AE75196009FAA1981BF86991203C8411F8980FDB"
            }
          }
        }
      }
    ],
    "minimum_receive": "123456"
  }
}
```

With CosmJS:

```js
import { toBinary } from "@cosmjs/cosmwasm-stargate";

const cw20Token = "terra1...token";

const result = await signingClient.execute(
  sender,
  cw20Token, // the message goes to the token contract
  {
    send: {
      contract: router,
      amount: "1000000",
      msg: toBinary({
        execute_swap_operations: {
          operations: cw20Operations,     // the hops above
          minimum_receive: minimumReceive, // from simulate_swap_operations, minus slippage
        },
      }),
    },
  },
  "auto"
);
```

Simulate CW20 routes the same way as native ones: pass the CW20 `token` asset info in the first operation.

## Response Data

When a route starts with a native asset, the transaction's response data holds the total amount received, as `SwapResponseData`:

```json
{
  "return_amount": "394395"
}
```

It is not set for routes that start with a CW20 `send`, because the CW20 contract replaces the response data.
