# Exit-Only Pools

## Overview

`astroport-pair-exit-only` is the code a pool is migrated to when it must only allow balanced withdrawals. It was written for the six Neutron pools drained in the 2026-09-22 incident. Their balances had gone to zero while their LP supply was unchanged, so a small deposit would have minted almost all LP tokens and taken the refill, and swaps would have traded the refill at stale prices. The pools were migrated to this code, then refilled with the returned assets, so their LPs can withdraw their share.

An exit-only pool:

- pays an LP its share of every asset the pool holds, rounded down, and burns the LP tokens;
- refuses deposits, swaps, config and ownership changes, and any other CW20 hook;
- answers the `pair`, `pool`, `share` and `simulate_withdraw` queries; every other query returns an exit-only error.

The migration doesn't write anything: the pool keeps its storage and its cw2 version, so a later build of its original contract that accepts that version could take it back.

<Admonition type="info" title="NOTE">
LP tokens staked in the [Incentives](../tokenomics/incentives.mdx) contract must be unstaked before they can be withdrawn.
</Admonition>

## InstantiateMsg

None. The code can't be instantiated; pools can only be migrated to it.

## MigrateMsg

The migrate message is empty. Supported pool contracts are `astroport-pair-concentrated` (1.x and 4.x), `astroport-pair-concentrated-duality` and `astroport-pair-transmuter`. Migration is refused for other contracts, for a config that names another address, and for a pool already in `pair_concentrated` 4.3's exit-only mode (which withholds an asset). Migrating again changes nothing.

## ExecuteMsg

### `withdraw_liquidity`

For pools with a native (tokenfactory) LP token. Attach the LP tokens as funds, for example `factory/neutron18c8qejysp4hgcfuxdpj4wf29mevzwllz5yh8uayjxamwtrs0n9fshq9vtv/astroport/share` for NTRN/USDC. The examples below use that pool. `assets` must be empty, and the call fails if the share would receive nothing.

<CH.Section>
<CH.Code>

```json json
{
  "withdraw_liquidity": {
    "assets": [],
    "min_assets_to_receive": [
      {
        "info": {
          "native_token": {
            "denom": "untrn"
          }
        },
        "amount": "990000"
      },
      {
        "info": {
          "native_token": {
            "denom": "ibc/B559A80D62249C8AA07A380E2A2BEA6E5CA9A6F079C912C3A9E9B494105E4F81"
          }
        },
        "amount": "1200000"
      }
    ]
  }
}
```

```rust pair.rs
WithdrawLiquidity {
    #[serde(default)]
    assets: Vec<Asset>,
    min_assets_to_receive: Option<Vec<Asset>>,
},
```

</CH.Code>

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`assets`](focus://json#3) | [`Vec<Asset>`](../common-types.mdx#asset) | Must be empty. One-sided withdrawals are refused |
| [`min_assets_to_receive`](focus://json#4:21) | `Option<Vec<Asset>>` | Fails the withdrawal if less than these amounts would be returned |

</CH.Section>

### `receive`

For pools with a CW20 LP token (USDC/DYDX, wstETH/WETH and axlUSDC/USDC). Execute `send` on the LP token contract with the pool as `contract` and a base64-encoded `withdraw_liquidity` hook. The hook takes the same fields as above, and any other hook is refused.

<CH.Section>
<CH.Code>

```json json
{
  "send": {
    "contract": "neutron1j4xpv03fw664mvntlhqnzp5hjqk2nfw00vrgx9qlq97rxc9fu3lqvmszl2",
    "amount": "1000000",
    "msg": "eyJ3aXRoZHJhd19saXF1aWRpdHkiOnt9fQ=="
  }
}
```

</CH.Code>

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`contract`](focus://json#3) | `String` | The pool address (here USDC/DYDX) |
| [`amount`](focus://json#4) | `Uint128` | The amount of LP tokens to withdraw |
| [`msg`](focus://json#5) | `Binary` | Base64 of `{"withdraw_liquidity":{}}` |

</CH.Section>
