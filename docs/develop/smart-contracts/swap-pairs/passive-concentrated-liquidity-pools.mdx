# Passive Concentrated Liquidity Pools

## Overview

Astroport's passive concentrated liquidity (PCL) pools optimize for a passive and automatic LP experience for concentrated liquidity. Instead of depositors actively managing their price ranges, liquidity becomes concentrated around an internal oracle price, the moving average of recent trades in a pair.

More details around how PCL pools function can be found [here](/docs/learn/astro-pools/passive-concentrated-liquidity-pools/passive-concentrated-liquidity-pools-intro).

PCL pools are a custom pool type (`{"custom": "concentrated"}`) and hold two assets. New pools mint a tokenfactory LP denom, `factory/<pool address>/astroport/share`. The pool owner (the factory owner unless ownership was transferred) can change its parameters.

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`amp`](focus://json#2) | `Decimal` | Amplification coefficient; affects trades close to `price_scale` |
| [`gamma`](focus://json#3) | `Decimal` | How gradually the curve moves from constant sum to constant product as the price moves away from `price_scale`. Lower is more gradual |
| [`mid_fee`](focus://json#4) | `Decimal` | The minimum fee, charged when the pool is balanced |
| [`out_fee`](focus://json#5) | `Decimal` | The maximum fee, charged when the pool is imbalanced |
| [`fee_gamma`](focus://json#6) | `Decimal` | How gradually the fee moves from `mid_fee` to `out_fee` |
| [`repeg_profit_threshold`](focus://json#7) | `Decimal` | Minimum profit before a repeg |
| [`min_price_scale_delta`](focus://json#8) | `Decimal` | Minimum change of `price_scale` when repegging |
| [`price_scale`](focus://json#9) | `Decimal` | Initial price scale: 1 x[0] = price_scale * x[1] |
| [`ma_half_time`](focus://json#10) | `u64` | Half-time of the internal price oracle, in seconds |
| [`track_asset_balances`](focus://json#11) | `Option<bool>` | Record asset balances per block. Can't be turned off later |
| [`fee_share`](focus://json#12) | `Option<FeeShareConfig>` | Fee sharing: `{ "bps": u16, "recipient": Addr }` |
| [`allowed_xcp_profit_drop`](focus://json#13) | `Option<Decimal>` | Allowed drop of xCP profit on each repeg attempt |
| [`xcp_profit_losses_threshold`](focus://json#14) | `Option<Decimal>` | Cap on total xCP profit losses |

### `provide_liquidity`

Deposits assets into the pool and mints LP tokens. Native assets are attached to the message as funds. CW20 assets are pulled with `transfer_from`, so you must first increase the pool's allowance for them. On the first deposit, a small amount of LP is minted to the pool itself and stays locked. The first deposit needs both assets; after that, single-sided deposits are accepted.

<CH.Section>
<CH.Code>

```json json
{
  "provide_liquidity": {
    "assets": [
      {
        "info": {
          "native_token": {
            "denom": "ibc/8D8A7F7253615E5F76CB6252A1E1BD921D5EDB7BBAAF8913FB1C77FF125D9995"
          }
        },
        "amount": "1000000"
      },
      {
        "info": {
          "native_token": {
            "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
          }
        },
        "amount": "1000000"
      }
    ],
    "slippage_tolerance": "0.01",
    "auto_stake": true,
    "receiver": "terra1...",
    "min_lp_to_receive": "990000"
  }
}
```

```rust pair.rs
ProvideLiquidity {
    assets: Vec<Asset>,
    slippage_tolerance: Option<Decimal>,
```

</CH.Code>

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`assets`](focus://json#3:20) | [`Vec<Asset>`](../common-types.mdx#asset) | The assets to deposit |
| [`slippage_tolerance`](focus://json#21) | `Option<Decimal>` | Fails the deposit if the pool price moves more than this against the deposit ratio |

### `withdraw_liquidity`

Burns LP tokens and returns the matching share of each pool asset. Attach the LP tokens (the pool's tokenfactory denom, for example `factory/terra1...pool/astroport/share`) as funds. Only balanced withdrawals are allowed: leave `assets` empty, otherwise the call fails. LP tokens staked in Incentives must be unstaked first. Older pools with a CW20 LP token are withdrawn from by sending the LP token to the pool with a `{"withdraw_liquidity":{}}` hook.

<CH.Section>
<CH.Code>

```json json
{
  "withdraw_liquidity": {
    "assets": [],
    "min_assets_to_receive": [
      {
        "info": {
          "native_token": {
            "denom": "uluna"
          }
        },
        "amount": "990000"
      },
      {
        "info": {
          "native_token": {
            "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
          }
        },
        "amount": "247000"
      }
    ]
  }
}
```

```rust pair_concentrated.rs
        fee_share_bps: u16,
        fee_share_address: String,

    pub mid_fee: Option<Decimal>,

    pub fee_gamma: Option<Decimal>,
    pub repeg_profit_threshold: Option<Decimal>,
    pub min_price_scale_delta: Option<Decimal>,

    pub allowed_xcp_profit_drop: Option<Decimal>,
    pub xcp_profit_losses_threshold: Option<Decimal>,

    pub next_gamma: Decimal,
    pub future_time: u64,

```

</CH.Code>

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`params`](focus://json#3) | `Binary` | Base64-encoded `ConcentratedPoolUpdateParams` |

| **Variants** | **Description** |
| ----------- | ----------- |
| `update { ... }` | Changes the fee parameters, `repeg_profit_threshold`, `min_price_scale_delta`, `ma_half_time` and the xCP profit limits immediately. Every field is optional |
| `promote { next_amp, next_gamma, future_time }` | Moves amp and gamma gradually to the new values, reached at `future_time` |
| `stop_changing_amp_gamma {}` | Stops an amp/gamma change and keeps the current values |
| `enable_fee_share { fee_share_bps, fee_share_address }` | Sends `fee_share_bps` of each swap's fee to `fee_share_address`. Greater than 0 and at most 1000 (10%) |
| `disable_fee_share` | Stops fee sharing |

</CH.Section>

## MigrateMsg

Version 4.3 adds an optional exit-only mode to the migration. Migrating with `exit_only` set stops swaps, deposits and price queries, and later withdrawals pay out every asset except `withheld`, which stays in the pool. Only a migration sets it and there is no way back out. This is separate from the [exit-only pool contract](./exit-only-pools.mdx), which pays out every asset.

<CH.Section>
<CH.Code>

```json json
{
  "exit_only": {
    "withheld": {
      "native_token": {
        "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
      }
    }
  }
}
```

```rust pair_concentrated/state.rs
#[cw_serde]
pub struct MigrateMsg {
    #[serde(default)]
    pub exit_only: Option<ExitOnly>,
}

#[cw_serde]
pub struct ExitOnly {
    pub withheld: AssetInfo,
}
```

</CH.Code>

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`exit_only`](focus://json#2:8) | `Option<ExitOnly>` | If set, puts the pool in exit-only mode with `withheld` kept in the pool. Omit it (`{}`) for a normal migration |

</CH.Section>
