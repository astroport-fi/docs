# Constant Product Pools

## Overview

The constant product pool uses the widely known xy=k formula. More details around how the pool functions can be found [here](/docs/learn/astro-pools/constant-product-pools).

A constant product pool holds two assets. New pools mint a tokenfactory LP denom, `factory/<pool address>/astroport/share`. The pool's owner for `update_config` is the factory owner.

## Links

- **Contract Repo:** https://github.com/astroport-fi/astroport-core/tree/main/contracts/pair
- **contract.rs:** https://github.com/astroport-fi/astroport-core/blob/main/contracts/pair/src/contract.rs
- **pair.rs:** https://github.com/astroport-fi/astroport-core/blob/main/packages/astroport/src/pair.rs
- **Tests:** https://github.com/astroport-fi/astroport-core/tree/main/contracts/pair/tests
- **Version documented:** `astroport-pair` 2.2.0 (astroport-core main). Pools created at different times can run older versions; a pool's cw2 `contract_info` shows its version.

## InstantiateMsg

Pools are instantiated by the [factory](../factory.mdx#create_pair), not directly. The factory passes this message to the pool; you only choose `pair_type`, `asset_infos` and `init_params` in `create_pair`.

<CH.Section>
<CH.Code>

```json json
{
  "pair_type": {
    "xyk": {}
  },
  "asset_infos": [
    {
      "native_token": {
        "denom": "uluna"
      }
    },
    {
      "native_token": {
        "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
      }
    }
  ],
  "token_code_id": 69,
  "factory_addr": "terra14x9fr055x5hvr48hzy2t4q7kvjvfttsvxusa4xsdcy702mnzsvuqprer8r",
  "init_params": "eyJ0cmFja19hc3NldF9iYWxhbmNlcyI6dHJ1ZX0="
}
```

```rust pair.rs
#[cw_serde]
pub struct InstantiateMsg {
    pub pair_type: PairType,
    pub asset_infos: Vec<AssetInfo>,
    pub token_code_id: u64,
    pub factory_addr: String,
    pub init_params: Option<Binary>,
}
```

</CH.Code>

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`pair_type`](focus://json#2:4) | [`PairType`](../factory.mdx#pairtype) | The pool type |
| [`asset_infos`](focus://json#5:16) | [`Vec<AssetInfo>`](../common-types.mdx#assetinfo) | The two assets in the pool |
| [`token_code_id`](focus://json#17) | `u64` | CW20 code ID kept in the factory config. New pools use a tokenfactory LP denom, so it isn't used for the LP token |
| [`factory_addr`](focus://json#18) | `String` | The factory contract address |
| [`init_params`](focus://json#19) | `Option<Binary>` | Optional base64-encoded `XYKPoolParams`: `{"track_asset_balances": true}` records asset balances per block for [`asset_balance_at`](#asset_balance_at). It can't be turned off later |

</CH.Section>

## ExecuteMsg

### `receive`

CW20 receive hook. A CW20 offer asset is swapped by sending it to the pool with the CW20 `send` message and a base64-encoded `swap` hook. CW20 tokens can't be swapped with `swap` directly.

<CH.Section>
<CH.Code>

```json json
{
  "receive": {
    "sender": "terra1...",
    "amount": "1000000",
    "msg": "<base64_encoded_json_string>"
  }
}
```

```rust pair.rs
Receive(Cw20ReceiveMsg),
```

</CH.Code>

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`receive`](focus://json#2:6) | [`Cw20ReceiveMsg`](https://docs.rs/cw20/latest/cw20/struct.Cw20ReceiveMsg.html) | CW20 receive message |

</CH.Section>

#### `Cw20HookMsg::Swap`

The hook embedded in `msg`. The offer asset and amount come from the CW20 transfer.

<CH.Section>
<CH.Code>

```json json
{
  "swap": {
    "ask_asset_info": {
      "native_token": {
        "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
      }
    },
    "belief_price": "0.25",
    "max_spread": "0.005",
    "to": "terra1..."
  }
}
```

```rust pair.rs
#[cw_serde]
pub enum Cw20HookMsg {
    Swap {
        ask_asset_info: Option<AssetInfo>,
        belief_price: Option<Decimal>,
        max_spread: Option<Decimal>,
        to: Option<String>,
    },
}
```

</CH.Code>

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`ask_asset_info`](focus://json#3:7) | [`Option<AssetInfo>`](../common-types.mdx#assetinfo) | The asset to receive. Optional in a two-asset pool |
| [`belief_price`](focus://json#8) | `Option<Decimal>` | The price the trader expects, used with `max_spread` |
| [`max_spread`](focus://json#9) | `Option<Decimal>` | Maximum spread allowed. Defaults to 0.5%, at most 50% |
| [`to`](focus://json#10) | `Option<String>` | Recipient of the ask asset. Defaults to the CW20 sender |

</CH.Section>

### `provide_liquidity`

Deposits assets into the pool and mints LP tokens. Native assets are attached to the message as funds. CW20 assets are pulled with `transfer_from`, so you must first increase the pool's allowance for them. On the first deposit, a small amount of LP is minted to the pool itself and stays locked.

<CH.Section>
<CH.Code>

```json json
{
  "provide_liquidity": {
    "assets": [
      {
        "info": {
          "native_token": {
            "denom": "uluna"
          }
        },
        "amount": "1000000"
      },
      {
        "info": {
          "native_token": {
            "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
          }
        },
        "amount": "1000000"
      }
    ],
    "slippage_tolerance": "0.01",
    "auto_stake": true,
    "receiver": "terra1...",
    "min_lp_to_receive": "990000"
  }
}
```

```rust pair.rs
ProvideLiquidity {
    assets: Vec<Asset>,
    slippage_tolerance: Option<Decimal>,
    auto_stake: Option<bool>,
    receiver: Option<String>,
    min_lp_to_receive: Option<Uint128>,
},
```

</CH.Code>

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`assets`](focus://json#3:20) | [`Vec<Asset>`](../common-types.mdx#asset) | The assets to deposit |
| [`slippage_tolerance`](focus://json#21) | `Option<Decimal>` | Fails the deposit if the pool price moves more than this against the deposit ratio |
| [`auto_stake`](focus://json#22) | `Option<bool>` | If true, the minted LP tokens are staked in the [Incentives](../tokenomics/incentives.mdx) contract on behalf of `receiver`. Defaults to false |
| [`receiver`](focus://json#23) | `Option<String>` | Receiver of the LP tokens. Defaults to the sender |
| [`min_lp_to_receive`](focus://json#24) | `Option<Uint128>` | Fails the deposit if fewer LP tokens would be minted |

</CH.Section>

### `withdraw_liquidity`

Burns LP tokens and returns the matching share of each pool asset. Attach the LP tokens (the pool's tokenfactory denom, for example `factory/terra1...pool/astroport/share`) as funds. Only balanced withdrawals are allowed: leave `assets` empty, otherwise the call fails. LP tokens staked in Incentives must be unstaked first. Older pools with a CW20 LP token are withdrawn from by sending the LP token to the pool with a `{"withdraw_liquidity":{}}` hook.

<CH.Section>
<CH.Code>

```json json
{
  "withdraw_liquidity": {
    "assets": [],
    "min_assets_to_receive": [
      {
        "info": {
          "native_token": {
            "denom": "uluna"
          }
        },
        "amount": "990000"
      },
      {
        "info": {
          "native_token": {
            "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
          }
        },
        "amount": "247000"
      }
    ]
  }
}
```

```rust pair.rs
WithdrawLiquidity {
    #[serde(default)]
    assets: Vec<Asset>,
    min_assets_to_receive: Option<Vec<Asset>>,
},
```

</CH.Code>

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`assets`](focus://json#3) | [`Vec<Asset>`](../common-types.mdx#asset) | Must be empty. Imbalanced withdrawals are disabled |
| [`min_assets_to_receive`](focus://json#4:21) | `Option<Vec<Asset>>` | Fails the withdrawal if less than these amounts would be returned |

</CH.Section>

```json json
      "info": {
        "native_token": {
          "denom": "uluna"
        }
      },
      "amount": "1000000"
    },
    "ask_asset_info": {
      "native_token": {
        "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
      }
    },
    "belief_price": "0.25",
    "max_spread": "0.005",
    "to": "terra1..."
  }
}
```

```rust pair.rs

    offer_asset: Asset,
    ask_asset_info: Option<AssetInfo>,
    belief_price: Option<Decimal>,
    max_spread: Option<Decimal>,
    to: Option<String>,
},
```

</CH.Code>

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`offer_asset`](focus://json#3:10) | [`Asset`](../common-types.mdx#asset) | The asset and amount to swap. Must match the attached funds |
| [`ask_asset_info`](focus://json#11:15) | [`Option<AssetInfo>`](../common-types.mdx#assetinfo) | The asset to receive. Optional in a two-asset pool |

</CH.Section>

### `update_config`

Enables or disables swap fee sharing. Only the factory owner can call it. `params` is a base64-encoded `XYKPoolUpdateParams`.

<CH.Section>
<CH.Code>

```json json
{
  "update_config": {
    "params": "eyJlbmFibGVfZmVlX3NoYXJlIjp7ImZlZV9zaGFyZV9icHMiOjUwMCwiZmVlX3NoYXJlX2FkZHJlc3MiOiJ0ZXJyYTEuLi4ifX0="
  }
}
```

```rust pair.rs
UpdateConfig { params: Binary },

#[cw_serde]
pub enum XYKPoolUpdateParams {
    EnableFeeShare {
        fee_share_bps: u16,
        fee_share_address: String,
    },
    DisableFeeShare,
}
```

</CH.Code>

| **Params** | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`params`](focus://json#3) | `Binary` | Base64-encoded `XYKPoolUpdateParams` |

| **Variants** | **Description** |
| ----------- | ----------- |
| `enable_fee_share { fee_share_bps, fee_share_address }` | Sends `fee_share_bps` of each swap's fee to `fee_share_address`. Greater than 0 and at most 1000 (10%) |
| `disable_fee_share` | Stops fee sharing |

</CH.Section>

<Admonition type="info" title="NOTE">
Constant product pools don't support `propose_new_owner`, `drop_ownership_proposal` or `claim_ownership`: their owner is always the factory owner.
</Admonition>

### `asset_balance_at`

Returns the pool's balance of an asset just before the given block height, or `null` if balances weren't tracked then. Balances are only tracked if the pool was created with `track_asset_balances` set.

<CH.Section>
<CH.Code>

### `simulate_provide`

Returns the amount of LP tokens a deposit would mint, as a `Uint128`.

<CH.Section>
<CH.Code>

```json json
{
  "simulate_provide": {
    "assets": [
      {
        "info": {
          "native_token": {
            "denom": "uluna"
          }
        },
        "amount": "1000000"
      },
      {
        "info": {
          "native_token": {
            "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
          }
        },
        "amount": "250000"
      }
    ],
    "slippage_tolerance": "0.01"
  }
}
```

```rust pair.rs
#[returns(Uint128)]
SimulateProvide {
    assets: Vec<Asset>,
    slippage_tolerance: Option<Decimal>,
```

| ----------- | ----------- | ----------- |

</CH.Section>
