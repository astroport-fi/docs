# Incentives

## Overview

The Incentives contract (formerly the Generator) is where LP tokens are staked to earn rewards. Rewards are distributed per second, pro rata to the LP tokens each staker has in a pool. It supports CW20 and tokenfactory LP tokens.

Under long-term support:

- **There are no ASTRO emissions.** `astro_per_second` is 0, there is no generator controller, and every Vesting schedule that funded emissions has ended. The emissions endpoints (`setup_pools`, `set_tokens_per_second`) are owner-only and unused.
- **Anyone can add external incentive schedules** to any pool registered in the factory, in any token that isn't blocked. A schedule that adds a reward token new to the pool pays the incentivization fee.
- **[yASTRO](./yastro) forwards pools' yASTRO rewards here** (`forward_pool_rewards`) as one-week schedules for the pools' LP stakers. On Terra, yASTRO is exempt from the incentivization fee.

The legacy Generator 2.3.2 contracts still exist on both chains, but emissions ended and they are not part of the protocol. See the [Retired](../contract-addresses#retired) addresses.

## Concepts

### Schedules and periods

Reward schedules are counted in periods of one week. Each period starts on Monday 00:00 UTC. A new schedule starts right away and lasts **until the next Monday plus `duration_periods` weeks**, so the shortest schedule lasts between 7 days and 1 second and 14 days, depending on the day it's added. A schedule lasts at most 25 periods (about 6 months).

The reward is spread evenly over the schedule: `rps = amount / (end - now)`. It must be at least 1 unit per second, otherwise `incentivize` fails. Overlapping schedules for the same reward token are added up.

A pool can have at most 5 external reward tokens at a time. A reward token whose schedules end is removed from the pool, and its next schedule counts as a new reward token again, so incentivizers are encouraged to keep schedules running without breaks.

### Incentivization fee

The first schedule of a reward token in a pool (a token the pool doesn't currently have as a reward) pays the incentivization fee. On both chains the fee is 1,500 ASTRO (`1500000000` units of ASTRO), sent to the Maker. Attach it to the `incentivize` call next to the reward.

No fee is due when:

- the pool already has the reward token,
- the reward is ASTRO,
- the sender is on the fee exemption list (Terra 1.5.0 only; yASTRO is on it).

Use [`is_fee_expected`](#is_fee_expected) to check before sending.

### Staking LP tokens

Any LP token of a pool registered in the factory can be staked, whether or not the pool has rewards. Rewards are claimed automatically on every `deposit` and `withdraw`, or with `claim_rewards`. When a pool's `provide_liquidity` is called with `auto_stake: true`, the pool stakes the new LP tokens here for the provider.

Rewards that accrue while nobody is staked in a pool are "orphaned". The owner can collect them with `claim_orphaned_rewards`.

## ExecuteMsg

### `deposit`

Stakes the attached tokenfactory LP tokens, on behalf of `recipient` if set (otherwise the sender). Pending rewards are claimed first.

```json
{
    "deposit": {
        "recipient": "terra1..."
    }
}
```

### `receive`

Stakes CW20 LP tokens. Send them to the Incentives contract with a CW20 `send` whose `msg` is the base64 of the hook below.

<CH.Section>
    <CH.Code>

        ```json json
        {
            "send": {
                "contract": "terra1eywh4av8sln6r45pxq45ltj798htfy0cfcf7fy3pxc2gcv6uc07se4ch9x",
                "amount": "1000000",
                "msg": "eyJkZXBvc2l0Ijp7fX0="
            }
        }
        ```

        ```rust incentives.rs
        #[cw_serde]
        pub enum Cw20Msg {
            Deposit {
                recipient: Option<String>,
            },
            DepositFor(String),
        }
        ```

    </CH.Code>

`eyJkZXBvc2l0Ijp7fX0=` is `{"deposit":{}}`. `deposit_for` is kept for older pool contracts.

</CH.Section>

### `withdraw`

Unstakes `amount` of an LP token. Pending rewards are claimed first.

```json
{
    "withdraw": {
        "lp_token": "terra1s275y73lfupag0g03nglxaedfnsw5z4m5zc9wk66guy503zuw5ss889tlx",
        "amount": "1000000"
    }
}
```

`lp_token` is the CW20 address or the tokenfactory denom of the LP token.

### `claim_rewards`

Claims every pending reward for the listed LP tokens.

```json
{
    "claim_rewards": {
        "lp_tokens": [
            "terra1s275y73lfupag0g03nglxaedfnsw5z4m5zc9wk66guy503zuw5ss889tlx"
        ]
    }
}
```

### `incentivize`

Adds a reward schedule to a pool. Anyone can call it. Attach the reward (a native coin) and, if it's due, the incentivization fee. For a CW20 reward, first give the Incentives contract an allowance for the amount; it pulls the tokens with `transfer_from`.

This example adds a 4-week USDC.inj schedule to the Terra LUNA/USDC pool's LP token:

<CH.Section>
    <CH.Code>

        ```json json
        {
            "incentivize": {
                "lp_token": "terra1s275y73lfupag0g03nglxaedfnsw5z4m5zc9wk66guy503zuw5ss889tlx",
                "schedule": {
                    "reward": {
                        "info": {
                            "native_token": {
                                "denom": "ibc/E8481AD838C31D4FC12A504B10F9B4E2F830F8818D2735C2FFC707579B5FA60B"
                            }
                        },
                        "amount": "5000000000"
                    },
                    "duration_periods": 4
                }
            }
        }
        ```

        ```rust incentives.rs
        #[cw_serde]
        pub struct InputSchedule {
            pub reward: Asset,
            pub duration_periods: u64,
        }
        ```

    </CH.Code>

| **Params**      | **Type** | **Description** |
| ----------- | ----------- | ----------- |
| [`lp_token`](focus://json#3)   | `String`        | The pool's LP token: a CW20 address or a tokenfactory denom         |
| [`reward`](focus://json#5:12)   | [`Asset`](../common-types#asset)        | The reward token and the total amount for the whole schedule         |
| [`duration_periods`](focus://json#13)   | `u64`        | Whole weeks after the next Monday, from 1 to 25         |

</CH.Section>

### Owner messages

| Message | Who | What |
| :-- | :-- | :-- |
| `update_config { astro_token?, vesting_contract?, generator_controller?, guardian?, incentivization_fee_info?, token_transfer_gas_limit? }` | owner | Changes general settings. `token_transfer_gas_limit` is between 400,000 and 1,500,000 |
| `update_fee_exemptions { add, remove }` | owner | Adds or removes senders that never pay the incentivization fee. Terra 1.5.0 only |
| `update_blocked_tokens_list { add, remove }` | owner or guardian | Blocked tokens can't be used as rewards, and pools containing them can't get ASTRO emissions |
| `remove_reward_from_pool { lp_token, reward, bypass_upcoming_schedules, receiver }` | owner | Removes a reward token from a pool and sends its remaining rewards to `receiver` |
| `claim_orphaned_rewards { limit?, receiver }` | owner | Sends orphaned rewards to `receiver` |
| `setup_pools { pools }`, `set_tokens_per_second { amount }` | owner (or generator controller for `setup_pools`) | ASTRO emissions. Unused: emissions are zero |
| `deactivate_pool { lp_token }` | factory | Called when the factory deregisters a pool |
| `deactivate_blocked_pools {}` | anyone | Removes active pools whose pair type is blocked |
| `propose_new_owner`, `drop_ownership_proposal`, `claim_ownership` | owner / proposed owner | Two-step ownership transfer |

On Terra, yASTRO is exempt from the fee:

```json
{
    "update_fee_exemptions": {
        "add": [
            "terra1fe8uj96z7f4jfsnkrdxhchxdhdtx8alr9zjqze76hm2ga6tpxjjq5rdjw7"
        ],
        "remove": []
    }
}
```

### `pool_info`

Total LP staked, every reward with its rate and index, and the last update time.

<CH.Section>
    <CH.Code>

        ```json json
        {
            "pool_info": {
                "lp_token": "terra1s275y73lfupag0g03nglxaedfnsw5z4m5zc9wk66guy503zuw5ss889tlx"
            }
        }
        ```

        ```rust incentives.rs
        #[cw_serde]
        pub struct PoolInfoResponse {
            pub total_lp: Uint128,
            pub rewards: Vec<RewardInfo>,
            pub last_update_ts: u64,
        }

        #[cw_serde]
        pub struct RewardInfo {
            pub reward: RewardType,
            pub rps: Decimal256,

        ```

    </CH.Code>

Each reward is either `{"int": <AssetInfo>}` (ASTRO emissions, no longer used) or `{"ext": {"info": <AssetInfo>, "next_update_ts": ...}}` (an external schedule). `reward_info { lp_token }` returns the same `Vec<RewardInfo>` on its own.

</CH.Section>

### `fee_exemptions`

The addresses that don't pay the incentivization fee, paginated (Terra 1.5.0 only). On Terra it returns `["terra1fe8uj96z7f4jfsnkrdxhchxdhdtx8alr9zjqze76hm2ga6tpxjjq5rdjw7"]` (yASTRO).
